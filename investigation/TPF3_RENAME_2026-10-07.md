# Renaming and recolouring: local two-game validation

Validated on `feat/rename-acceptance`, Transport Fever 3 build 40408 (Steam,
Windows), 2026-10-07. One run, `target/game-runs/run-1006-234244`: the rig's
local server and two agent-started games on one PC, both players in the
room's one company. Ordinary GUI actions changed the world; a read-only
probe typed into each game's console only read it. No production relay and
no game-install file was touched. Both games were quit through
`app.quit(false)` from their consoles.

## Acceptance outcome

- Renaming a station, a vehicle, a town and a depot from their windows or
  the line manager, and recolouring a vehicle from its window, went to the
  room as `Rename` and `VehicleOp` `Recolor` and were applied in both games.
  A rename from the guest's game was applied in both as well.
- After every action the two games listed the same names for every named
  entity, and the room's rolling world checks matched at every window of
  the run. Nothing was refused, nothing failed to apply, and no action was
  sent again by itself.
- The `rename` acceptance gate is now enabled.
- Not exercised here: a rename refused for another company's station
  (both players shared one company), save and reload of the renamed
  world, names with spaces, and other platforms.

## The world

`tpf3mp_fixture_bus`: a 16 by 16 map (seed `tpf3mp`, 1990) with a road
depot, two bus stations east and west of the town of Eastleigh, Line 1
between them and one GM New Look Fishbowl bus on it, saved with the mod in
its mod list. A fixture saved without the mod cannot start a room: the
hook asks the mod's GUI to save the world for the room, and a world whose
save does not list the mod has no GUI script to answer, so the save times
out every 120 s and the guest waits at its menu.

## Actions and what each game did

| # | Game | Action, as a player does it | Handed to the room | Applied |

| 1 | host | Station window title: "Eastleigh Station Transfer" to "WestStop" | `Rename` x2 (the game renames the station group and its building) | both games |
| 2 | host | Line manager, the vehicle's pencil: "Road Vehicle 1" to "BusOne" | `Rename` x1 | both games |
| 3 | host | Vehicle window, the consist row's paint button: red | `VehicleOp` `Recolor` x1 | both games |
| 4 | host | Town window title: "Eastleigh" to "Eastville" | `Rename` x2 | both games |
| 5 | host | Depot window title: "Eastleigh Road Depot" to "MainDepot" | `Rename` x2 | both games |
| 6 | guest | Station window title: "Eastleigh Station" to "EastStop" | `Rename` x2 | both games |

Every `hook.log` line `the game applied the room's actions between
simulation updates` has a counterpart in the other game: 21 in each by the
end. Neither log has a `not applied`, a refusal or a divergence. The rig
reported none either.

Two more actions came from the test harness rather than a deliberate
step, and are listed for completeness: at the start a click meant for the
station hit the line's map label, so the typed name renamed Line 1 to
"West" (`EditLine` `Rename` x2, applied in both games, a channel that was
never gated); and once a probe line typed while a name field still had the
keyboard sent one more `Rename` of the bus (action 8), after which both
games still read "BusOne".

## Names and colours

A probe run in each game's console walked every town, industry,
construction, station group, station and transport vehicle, read its
`NAME` and `COLOR` components, and wrote the list to a file of that game's
own (`app.saveUserdata`). The lists were compared after every action:

| Probe | After | Entries | Lists differ |
| --- | --- | --- | --- |
| before | nothing | 134 | no |
| after1 | the line rename | 136 | no |
| after2 | the station rename | 136 | no |
| after3 | the vehicle rename | 138 | no |
| after4 | the recolour | 138 | no |
| after5 | the town and depot renames | 138 | no |
| after6 | the guest's station rename | 138 | no |
| after7 | two minutes of play | 138 | no |

The entry count grew as industries spawned, the same ones in both games.
The final list in both games holds `3872=Eastville`, `6823=BusOne`,
`6826=WestStop`, `6892=WestStop`, `7165=EastStop`, `7516=EastStop` and
`7503=MainDepot`. The bus's colour was not readable through a `COLOR`
component on the vehicle entity; captures of both games show the bus red.

## Money

The probe also read the company balance. The two readings matched whenever
both games were probed within the same simulation second (79,781,032
before; 79,414,904; 78,316,035; 75,737,705 after the guest's rename) and
differed only by running costs when they were not; renaming and
recolouring cost nothing in either game. The room's rolling checks, which
include the money lanes, matched throughout.

## The worlds stayed equal

The determinism probe mod was not in the fixture, so `probes.ps1` had no
samples. The mod's own rolling world checks served instead: each
`hook.log` holds a signature for every window of 50 steps, and the two
games' signatures were compared window by window: 181 windows, steps 1 to
9050, all 181 equal, none missing on either side.

## No echo

In the 120 s after the last rename, neither game handed a `Rename` or a
`VehicleOp` to the room (only `NotificationSeen`, a notification's sound).
Over the whole run the host handed 9 `Rename`/`VehicleOp` actions for its
5 deliberate renames and recolour (two per station, town and depot
rename, as the game sends them, plus the harness's extra one above); the
guest handed 2 for its one rename.

## Comparison limits and checks

- One PC, one Windows build, one company. Foreign-company refusals are
  covered by Lua fixtures only.
- Both probes of a pair were taken seconds apart in a running world, so
  only the room's checks compare the same step; the name lists do not
  change between steps unless renamed, so their equality holds.
- Vehicle colour was compared by eye in both games' captures, not by a
  component read.
- Names typed were ASCII without spaces.
